# ABC-XYZ анализ запасов

Расширение Akeda ERP: делит номенклатуру на классы по величине расхода (ABC) и
по его ровности (XYZ). Две страницы внутри Akeda — сводка на странице настройки
установки и класс товара на его карточке — и свой сервер на Go, который читает
Akeda публичным REST.

**Ничего не пишет.** Ни в Akeda, ни к себе на диск.

---

## Почему это расширение, а не функция продукта

Потому что методика — дело клиента. Один считает A по восьмидесяти процентам
расхода в деньгах, другой по семидесяти, третий меряет в штуках; период у всех
свой. Платформа, назначившая эти числа за клиента, была бы неправа у всех,
кроме одного. Пороги и период поэтому живут в настройке установки, а не в коде.

## Что оно показывает

**Панель на карточке товара** (слот `platform.embedded_panel.v1`, место
`core.product.card`): класс `A/B/C × X/Y/Z`, доля товара в расходе склада и
место в списке, расход за окно и в среднем за месяц, остаток, на сколько дней
его хватит, коэффициент вариации и отдельный признак «неподвижен».

**Страница настройки** (слот `platform.settings_page.v1`, место
`settings.page`): что сейчас применено, что из введённого не разобралось и
почему, какие склады нашлись по кодам, какое получилось окно и сводная таблица
`ABC × XYZ`.

## Как считается

Расход берётся из движений регистра `stock`, а не из строк документов: документ
бывает черновиком и отменённым, а регистр показывает то, что действительно
случилось со складом, — ровно те же числа, что кабинет видит в своём отчёте
остатков.

Пять решений расчёта названы явно, потому что именно на них ошибаются:

1. **Товар, переступающий границу, остаётся в верхнем классе.** Класс считается
   по накопленной доле ДО этого товара. Иначе при пороге 80 % и одном товаре,
   дающем 90 % расхода, класс A оказался бы пуст.
2. **Нулевой расход — всегда C**, и класса XYZ у такого товара нет вовсе:
   вариация относительна, а делить на нулевое среднее нечем.
3. **Ряд XYZ содержит нули.** Месяц без расхода — это наблюдение «ноль», а не
   отсутствие наблюдения. Выбросив его, мы получили бы ровный ряд у товара,
   проданного дважды за полгода.
4. **Отклонение считается по генеральной совокупности** (делим на `n`, не на
   `n-1`): окно — не выборка из чего-то большего, а всё, что рассматривается.
5. **Окно — целые календарные месяцы, заканчивая прошлым.** Незакрытый месяц
   короче остальных ровно на то, сколько его не прошло: третьего числа он даст
   десятую часть обычного расхода, и товар с ровными продажами получал бы Z
   каждое первое число. Свежесть от этого не страдает: «неподвижен ли товар»
   считается отдельным запросом с разрезом по дням и идёт до сегодняшнего.

Порог вариации **включающий**: значение ровно на пороге относится к верхнему
классу. Ряд короче `min_periods` не даёт буквы XYZ вовсе — по одному месяцу
вариация равна нулю, то есть «идеально ровный спрос» по одной отгрузке.

## Чего оно НЕ умеет

Список честный, а не список планов.

- **Не пишет в Akeda.** Ни одной операции записи в коде нет. Это первое живое
  расширение, и оно физически не должно уметь испортить учёт клиента.
- **Не считает по выручке и марже.** На складе их нет: регистр `stock` несёт
  себестоимость (`amount`) и количество (`qty`). Мера ABC — одно из этих двух.
- **Страница настройки ничего не сохраняет.** Значения вводит кабинет в Akeda;
  записи настройки установки во внешнем контуре нет вовсе — иначе приложение
  могло бы переставить порог, по которому кабинет думает, что оно считает.
  Страница показывает применённое, объясняет замечания и считает предпросмотр.
- **Не разделяет юрлица.** Расход и остаток складываются по всем `company`
  кабинета: контекст запуска юрлица не называет, а выбрать его на странице
  настройки нельзя, потому что сохранять выбор некуда (см. предыдущий пункт).
- **Не хранит историю.** Снимок расчёта живёт в памяти процесса и протухает
  через `STOCK_ABC_SNAPSHOT_TTL`. Перезапуск его теряет, и это правильно:
  снимок — не данные, а вывод из них.
- **Не подписано ни на одно событие.** Адрес `/events` объявлен потому, что
  hosted-приложение обязано его назвать, и отвечает `204`.
- **Не листает номенклатуру.** У списка товаров нет отбора по набору
  идентификаторов — только `q`, `folder` и `limit`, — поэтому имена читаются
  ровно для того товара, чью карточку открыли. Классы считаются по разрезу
  регистра, где товар назван идентификатором, а не именем.
- **Не установит себя само.** Завести приложение, опубликовать версию и
  поставить её кабинету умеет персонал платформы; токен установки выдаёт
  человек. Публичного обмена учётных данных на токен нет — см.
  [docs/state-of-the-contour.md](../../docs/state-of-the-contour.md).

## Настройка установки

Все поля необязательны: приложение работает на умолчаниях сразу после
установки. Значения вводит кабинет: **Настройки → Приложения → это приложение**.

| Ключ | Тип | Умолчание | Что задаёт |
|---|---|---|---|
| `period_months` | целое 1…36 | `6` | сколько целых месяцев в окне |
| `metric` | `amount`/`qty` | `amount` | мера ABC: себестоимость или количество расхода |
| `abc_a_percent` | число 0…100 | `80` | верхняя граница класса A |
| `abc_b_percent` | число 0…100 | `15` | ширина класса B; C — остаток |
| `xyz_x_max_percent` | число | `10` | потолок вариации класса X, % |
| `xyz_y_max_percent` | число | `25` | потолок вариации класса Y, % |
| `min_periods` | целое | `3` | короче ряда буква XYZ не ставится |
| `dead_days` | целое | `90` | сколько дней без расхода означают «лежит» |
| `warehouse_codes` | строка | пусто | коды складов через запятую; пусто — все |

Неразобранное значение не роняет приложение: берётся умолчание, а страница
настройки называет поле, введённое значение и причину. Приложение, молча
упавшее из-за опечатки в проценте, разбирают часами.

## Как поднять локально

Нужны действующая установка и её токен. Токен выдаёт человек — получить его
командой неоткуда.

```bash
export AKEDA_TENANT='ваш-кабинет'                 # slug КАБИНЕТА, не юрлица
export AKEDA_INSTALLATION_TOKEN='ai_live_…'       # или AKEDA_INSTALLATION_TOKEN_FILE
export STOCK_ABC_PUBLIC_URL='https://stock-abc.example.test'

go run ./examples/stock-abc
curl -s http://127.0.0.1:8090/healthz
```

| Переменная | Умолчание | Зачем |
|---|---|---|
| `AKEDA_TENANT` | — | обязательна: внешний контур требует `X-Tenant` у каждой операции |
| `AKEDA_INSTALLATION_TOKEN` | — | токен установки `ai_live_…` или `ai_test_…` |
| `AKEDA_INSTALLATION_TOKEN_FILE` | — | то же значение файлом; хвостовой перевод строки срезается |
| `AKEDA_BASE_URL` | `https://erp.akeda.ru` | контур Akeda |
| `AKEDA_SHELL_ORIGINS` | `https://erp.akeda.ru` | источники оболочки для моста сообщений |
| `STOCK_ABC_ADDR` | `:8090` | адрес прослушивания |
| `STOCK_ABC_PUBLIC_URL` | — | свой адрес; по нему сверяется источник рамки из контекста запуска |
| `STOCK_ABC_SNAPSHOT_TTL` | `15m` | как часто пересчитывать снимок |
| `STOCK_ABC_SESSION_TTL` | `30m` | сколько живёт сеанс открытой страницы |

**Флага для токена нет намеренно.** Аргументы командной строки видны любому
процессу на машине, и «удобно передать ключ флагом» стоит ровно столько же,
сколько сказать его вслух. Журнал печатает только контур токена — `ai_live_…`
или `ai_test_…`, — а поверх вывода стоит фильтр, вычищающий значение и из
чужого текста: адреса запроса, тела ответа, сообщения библиотеки.

Открыть страницы браузером напрямую нельзя: без контекста запуска они покажут
«Akeda не прислала контекст». Так и задумано — контекст приходит мостом
сообщений от оболочки, а не параметром адреса.

```bash
docker build -f examples/stock-abc/Dockerfile -t akeda-stock-abc .
docker run --rm -p 8090:8090 \
  -e AKEDA_TENANT -e AKEDA_INSTALLATION_TOKEN akeda-stock-abc
```

Контекст сборки — корень репозитория: расширение импортирует клиента из
`clients/go`.

## Перед подачей версии

Адреса в `app.json` — заглушки (`stock-abc.example.test`). Замените на свои
шесть: `runtime.webhookUrl`, `runtime.healthUrl`, `runtime.allowedOrigins`,
`ui[].url` у обоих слотов, `metadata.homepage` и `support.*`. Источник из
`ui[].url` обязан входить в `runtime.allowedOrigins`, иначе линтер платформы
откажет: согласие кабинета получено на один адрес, а страница открывалась бы с
другого.

### Линт манифеста

**Линтер платформы принимает манифест:**

```
$ manifest-lint -root <дерево Akeda ERP> examples/stock-abc/app.json
✅ manifest-lint: 1 manifest соответствуют контракту v1 (точек в реестре: 9, областей: 71, слотов интерфейса: 3)
```

**CLI этого репозитория — отказывает, и это его снимок, а не манифест:**

```
$ go run ./cmd/akeda manifest lint examples/stock-abc/app.json
  $.runtime: поле egress схемой не объявлено
  $.ui[0]: поле placements схемой не объявлено
  $.ui[1]: поле placements схемой не объявлено

найдено замечаний: 3
```

Оба замечания — про снимок контракта в `snapshot/`, а не про манифест. Он снят
до того, как платформа завела у слота обязательный массив `placements`
(именованные места) и перенесла `runtime.egress` из `runtime.resources` на
уровень выше. Схема снимка запрещает лишние поля, поэтому правильный сегодня
манифест она отвергает, а обязательного `placements` не требует вовсе.

Лечится снятием снимка на следующем релизе — `python3 scripts/snapshot.py
--source <дерево Akeda ERP>` и `python3 scripts/generate.py`, — а не правкой
манифеста: слот без `placements` платформа не примет, а пустой список мест
означает «нигде», а не «везде».

## Что где лежит

| Файл | Что в нём |
|---|---|
| `analysis.go` | расчёт ABC-XYZ: чистые функции без Akeda, HTTP и времени |
| `settings.go` | разбор настройки установки и окно из целых месяцев |
| `akeda.go` | вызовы Akeda — только чтение, шесть операций |
| `snapshot.go` | сбор данных, снимок и его кэш |
| `launch.go` | погашение токена запуска, проверки и сеансы страниц |
| `server.go` | маршруты, политика безопасности содержимого, ответы страницам |
| `secret.go` | секрет, который не печатается, и фильтр журнала |
| `web/` | страницы: свои стили и скрипты, ни одного внешнего адреса |
| `app.json` | манифест расширения |

## Проверки

```bash
gofmt -l .
go build ./...
go vet ./...
go test ./examples/stock-abc/
```

Тестами закрыты три места, где ошибка не видна глазом: границы классов
(товар-одиночка, значение ровно на пороге, нули в ряду, равные значения),
разбор контекста запуска (чужой nonce, чужой якорь, чужой слот, истёкший
сеанс) и то, что секрет не уходит в журнал — ни печатью структуры, ни
сериализацией, ни чужим текстом, в котором значение уже оказалось.
