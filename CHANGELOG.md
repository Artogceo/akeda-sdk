# Журнал изменений

Версия SDK и версия контракта — разные вещи. Контракт называет себя сам
(`info.version` опубликованного артефакта); SDK версионируется отдельно, потому
что рантайм и CLI меняются и без нового релиза Akeda.

## 0.1.0

Первый состав репозитория.

**Снимок контракта `0.21.0-core-public`**, отпечаток
`617b9ca2f197b89bd82bb574b4c916e595197a7292e49be74f1f7eb07987d7f8`:
770 операций (30 стадии `public`, 740 `preview`), 1014 схем, схема манифеста
расширения, контракт подписанной доставки с векторами, схемы слоя ссылок на
справочники. Снят скриптом из опубликованных артефактов Akeda.

**Клиенты.** TypeScript, Python и Go: сгенерированные типы плюс написанный
руками рантайм — учётные данные с проверкой префикса, заголовки кабинета,
листание `limit`/`offset` с отказом на просьбу сверх потолка, `Idempotency-Key`
только у пяти операций, которые его читают, разбор конверта отказа
(`code`/`detail`/`request_id`), повтор только там, где сервер сам просит, и
проверка подписи вебхука, сверенная с векторами контракта.

**CLI `akeda`.** Разведка контракта, вход в контур разработчика по одноразовой
ссылке, заявка на имя издателя, чтение своей установки токеном `ai_…`, линт
формы манифеста, проверка приёмника событий и полный conformance-набор без живой
Akeda.

**Примеры.** Первый вызов и приёмник событий на трёх языках; манифест
расширения, проходящий линт.

**Чего в этом составе нет намеренно.** Управления приложениями и версиями:
внешней двери к каталогу в опубликованном контракте нет, и команда, изображающая
её, врала бы дважды. Обращений к `sandbox.akeda.ru`: этого контура не существует.
Публикации пакетов: собрать можно, опубликовать — нет.
