# Точки расширения, функции, слоты, места, графы и события

Оси, которые легко перепутать, потому что все они отвечают на один вопрос — «как
приложение участвует в работе Akeda»:

- **точка расширения** — КОГДА Akeda зовёт приложение (или ждёт от него
  результата): жизненный цикл документа, поставщик классификации, проверка
  документа перед проведением;
- **функция** — ЧЕЙ КОД при этом работает: модуль WebAssembly, который платформа
  хранит у себя и исполняет внутри операции кабинета, без сети;
- **слот интерфейса** — КАК приложение выглядит на экране: пункт, который рисует
  оболочка; рамка со своим источником; страница настройки;
- **место** — ГДЕ этот слот стоит: карточка документа, панель действий товара,
  список контрагентов, страница настроек;
- **графа** — КАКИЕ СВОИ ПОЛЯ приложение добавляет карточкам кабинета.

Плюс события: приложение узнаёт о фактах, не спрашивая. Событие сообщает, ЧТО
произошло и С ЧЕМ; содержимое записи вы читаете public API своим токеном, и
кабинет видит этот поход.

Списки ниже сняты вместе с контрактом и лежат в снимке машинно:

```bash
go run ./cmd/akeda catalog              # точки, слоты и места целиком
go run ./cmd/akeda catalog placements   # только места
go run ./cmd/akeda catalog --json       # то же машинно
```

`akeda manifest lint` проверяет по этому же каталогу, а не по форме ключа: место
`crm.deal.sidebar` формально правильное и не существует, и слот, попросившийся
туда, не показался бы ни на одном экране — без единого отказа.

## 1. Точки расширения

Шесть. Ключ содержит версию: ломающее изменение формы — это НОВАЯ точка рядом со
старой, а не правка существующей.

| Ключ | Владелец | Модель | О чём |
|---|---|---|---|
| `core.document.before_post.v1` | `core` | sandbox | проверка документа перед проведением: функция вправе отказать, предупредить или промолчать |
| `core.document_lifecycle.v1` | `core` | async | документ создан, обновлён, проведён, отменён, помечен удалённым |
| `finance.classification_provider.v1` | `finance` | async | статья и контрагент приходят рекомендацией, которую оператор принимает или отклоняет |
| `platform.context_action.v1` | `platform` | sync | контекстное действие: пункт на экране записи |
| `platform.embedded_panel.v1` | `platform` | sync | изолированная панель: рамка со своим источником и мостом сообщений |
| `platform.settings_page.v1` | `platform` | sync | страница настройки установки по схеме конфигурации |

Три последние — слоты интерфейса: слот и есть точка расширения, у которой
владелец — модуль `platform`, потому что оболочка и состав разделов принадлежат
ему.

**Модель говорит, как владелец ждёт ответ, и она же решает, что вы вправе
сделать.**

| Модель | Кто отвечает | Право отказа |
|---|---|---|
| `sync` | ваш сервер по сети, внутри пользовательской операции | нет: вышел срок — владелец идёт дальше без ответа |
| `async` | ваш сервер отдельным вызовом позже | нет: к этому моменту всё уже случилось |
| `sandbox` | ВАШ КОД внутри Akeda, без сети | есть, и только у неё |

Право остановить операцию даёт только песочница, и внешнему приложению по сети
оно не даётся ни при каком сроке ожидания: там оно означало бы, что кабинет
перестаёт проводить документы, когда у издателя падает сервер, — цену за это
платит не издатель. Подробно — [§ 2](#2-функции-ваш-код-внутри-akeda).

**Раздел `extensionPoints` в манифесте необязателен.** Приложению, которому нужны
только события, перечислять там нечего: подписка объявляется в `subscriptions`.

**Песочничную точку в `extensionPoints` не пишут.** Исполнять по такой строке
нечего: у песочничной точки должен быть артефакт, а он объявляется разделом
`functions`. Строка без него обещает участие, которого не будет, — и
`akeda manifest lint` её отклоняет.

## 2. Функции: ваш код внутри Akeda

Функция — модуль WebAssembly, который платформа хранит у себя и исполняет в
момент, названный точкой расширения. У неё есть имя, точка, артефакт с
отпечатком и необязательный фильтр:

```json
"functions": [
  {
    "key": "purchase_limit",
    "point": "core.document.before_post.v1",
    "artifact": { "digest": "sha256:3b3b…3b" },
    "filter": { "document_type": ["purchase_receipt", "supplier_order"] }
  }
]
```

Раздел свой, а не строка в `extensionPoints`, потому что у функции есть то, чего
нет ни у слота, ни у подписки, — **артефакт**. Слот показывает вашу страницу,
подписка приносит факт на ваш сервер, а функция живёт у Akeda, и платформа
обязана знать, что исполняет ровно то, что прошло ворота публикации.

**Пять функций на версию** — потолок. Не потому, что шестая опаснее пятой, а
потому, что человек ждёт перед кнопкой «провести»: бюджет всей цепочки функций
кабинета — четверть секунды.

**Фильтр необязателен, и его отсутствие означает «на каждом документе
кабинета».** Умолчание широкое намеренно: об этом кабинету говорят словами на
экране согласия, а не прячут за молчанием.

**Сбой функции — не отказ.** Ловушка, истёкший бюджет, непонятный ответ,
отсутствующий артефакт — всё это означает, что вердикта нет, и проведение идёт.
Расширение с багом не останавливает кабинет. Настоящий отказ — только явный
`refuse`.

### Чего в контуре нет, и это состояние, а не умолчание

- **Артефакт грузит персонал платформы.** Портала функций у издателя нет:
  манифест объявляет отпечаток, а байты `.wasm` кладут не вашей рукой. Версия с
  необеспеченной функцией МОЛЧАЛИВА — кабинет её поставит, подпишет согласие
  «проверяет документы перед проведением» и не получит ни одной проверки, потому
  что исполнять нечего.
- **Исполнение выключено на всех стендах.** Флаг гасит ровно одно: связь ядра с
  диспетчером. Всё остальное — раздел манифеста, линтер, ворота публикации,
  хранение артефактов — работает и при выключенном флаге. Порядок именно такой:
  сначала контур поставки живёт и проверяется на каждой публикации, потом
  где-то включается исполнение.
- **Точка одна.** `core.document.before_post.v1`, и всё.

`akeda manifest lint` проверяет то, что проверяемо без Akeda: точка существует,
точка ПЕСОЧНИЧНАЯ, отпечаток нужной формы, имена функций не повторяются, права
точки запрошены манифестом. Вторая проверка здесь главная: функция на сетевой
точке не будет вызвана никогда — молчание, неотличимое от работы.

## 3. Слоты интерфейса

| Слот | Виды | Контекст запуска |
|---|---|---|
| `platform.context_action.v1` | `action` | `tenant_id`, `installation_id`, `module`, `entity`, `entity_id`, `locale` |
| `platform.embedded_panel.v1` | `iframe`, `panel` | те же плюс `actor_subject`, `theme` |
| `platform.settings_page.v1` | `settings` | `tenant_id`, `installation_id`, `actor_subject`, `locale`, `theme`, `module` |

Человека контекст называет ПСЕВДОНИМОМ (`actor_subject`), своим у каждой пары
«установка + человек». Имени, почты, числового идентификатора и ролей сотрудника
в словаре нет и не будет: реестр людей общий на всю платформу, и по числовому
идентификатору приложение, стоящее в двух кабинетах, связало бы двух разных
клиентов между собой.

У слота вида `action` адрес обязателен и означает не рамку, а ТОЧКУ ВЫЗОВА:
нажатие приходит не из браузера — Akeda подписывает запрос ключом установки и
зовёт ваш адрес со своего сервера. Проверять подпись надо ровно так же, как у
доставки событий ([webhooks.md](webhooks.md)).

Мост сообщений закрыт списком: страница шлёт `akeda.slot.ready`,
`akeda.slot.resize`, `akeda.slot.close`; оболочка шлёт `akeda.slot.launch` и
`akeda.slot.theme`. Сообщения «покажи текст», «перейди по адресу» и «позови за
меня API» в мосте нет — каждое из них отдавало бы недоверенной странице кусок
экрана или сессии человека.

## 4. Места

Двадцать два. Ключ — `<модуль>.<сущность>.<поверхность>`, либо
`<модуль>.<поверхность>` для места вне записи.

| Модуль | Сущности | Поверхности |
|---|---|---|
| `core` | `document`, `product`, `contact` | `card`, `toolbar`, `list` у каждой |
| `crm` | `deal` | `card`, `toolbar`, `list` |
| `stock` | `document` | `card`, `toolbar`, `list` |
| `stock` | `report` | `list` |
| `finance` | `transaction` | `card`, `toolbar`, `list` |
| `finance` | `settlement_document` | `card`, `toolbar` |
| `settings` | — | `page` (место вне записи: `settings.page`) |

Поверхностей четыре:

| Поверхность | Что это | Какие слоты | `entity_id` |
|---|---|---|---|
| `card` | основная область карточки записи | `action`, `iframe`, `panel`, `declarative` | есть |
| `toolbar` | ряд кнопок над этой же записью | `action` | есть |
| `list` | раздел со списком записей | `action` | нет |
| `page` | раздел целиком, вне записи | `settings`, `iframe`, `panel` | нет |

Четыре правила, на которых ошибаются:

- **пустой список означает «нигде», а не «везде»**. Место — часть того, на что
  соглашается кабинет, и слот без места не показывается;
- **место решает, какой вид слота принимает**. Рамка не встаёт в ряд кнопок: на
  `toolbar` и `list` помещается только `action`;
- **словарь контекста принадлежит месту**. Кнопка над списком не получает
  `entity_id` — записи под ней нет вовсе. Попросить у места то, чего оно не даёт,
  — ошибка манифеста, а не пустая панель в проде; `akeda manifest lint` называет
  такое поимённо;
- **набора выделенных строк не бывает**. Кнопка над списком не узнаёт, что
  человек отметил галочками: `selected[]` в словаре запуска нет. Нужные записи
  приложение выбирает своим токеном и своими одобренными областями.

Один слот вправе назвать несколько мест:

```json
{
  "slot": "platform.context_action.v1",
  "placements": ["core.document.card", "stock.document.toolbar"],
  "type": "action"
}
```

## 5. Свои графы в карточках кабинета

Справочник — это СПИСОК ЗНАЧЕНИЙ, графа — МЕСТО В КАРТОЧКЕ, куда значение
кладут. Одно без другого бесполезно, поэтому раздел `fields` живёт рядом с
`referenceData` и в том же пространстве имён `app.<издатель>.<ключ>.<поле>`.

```json
"fields": [
  {
    "entity": "core.product",
    "key": "vendor_grade",
    "type": "string",
    "label": { "ru": "Сорт поставщика", "en": "Supplier grade" },
    "required": false
  }
]
```

Платформа исполняет объявление сама: установка заводит графы в схеме полей
кабинета, обновление версии их обновляет, удаление применяет объявленный исход.
Отдельного контура записи значений нет — они лежат в `custom` самой карточки и
ходят обычными операциями сущности, теми же правами, что у человека.

| Слово | Что это значит |
|---|---|
| `entity` | `core.product`, `core.contact`, `crm.deal`. Список закрыт: у остальных сущностей нет ни блока дополнительных полей, ни места под значения |
| `type` | `string`, `text`, `number`, `boolean`, `date`, `enum`, `reference`. Список закрыт и у живой графы не меняется |
| `label`, `description` | На русском и английском: графа стоит в карточке рядом с полями кабинета, а карточку Akeda показывает на двух языках |
| `options` | Значения перечисления с кодом и подписью. Только у `enum` |
| `reference.directory` | Ключ справочника, который ЭТО ЖЕ приложение объявило в `referenceData.provides`. Только у `reference` |
| `uninstall` | `archive` (по умолчанию) или `transfer` — что станет с графой при удалении приложения |
| `obsolete` | Графа больше не нужна: уходит с карточек, значения остаются |

Предел — **двадцать граф на одну сущность** у одного приложения. Предел про
карточку, а не про базу: две дюжины чужих граф превращают форму товара в анкету,
в которой не найти собственные поля кабинета.

Четыре правила, на которых ошибаются:

- **`required: true` не бывает.** Обязательность — это запрет сохранить карточку,
  и приложение, поставившее его на чужую форму, останавливает работу там, где о
  приложении никто не думал: карточку товара заводят в приёмке, а не в вашем
  разделе. Схема принимает только `false`;
- **тип живой графы не меняется**, как и её справочник и сущность. В графе лежат
  значения кабинета: число, прочитанное как дата, — не ошибка, а другой ответ.
  Ворота публикации отклоняют такую версию до кабинетов, а не в них;
- **объявление нельзя убрать.** Единственный законный отказ от собственной графы
  — `"obsolete": true`: графа уходит с форм, значения остаются читаемыми;
- **ссылаться можно только на свой справочник.** Ключи списков, которые кабинет
  завёл сам, придумал человек, и угадать их приложение не может. `akeda manifest
  lint` отклоняет ссылку на справочник, которого этот же манифест не заводит.

Удаление приложения значений НЕ стирает ни в одном исходе: `archive` убирает
графу с карточек, `transfer` передаёт её кабинету.

**Сделки установке закрыты вовсе**: у контура CRM нет операций для установки, и
графу на карточке сделки заполняет только человек. Объявить её приложение может
— заполнять её будет ваш клиент.

## 6. События

Тема — имя факта плюс версия схемы тела: `core.document.posted.v1`. Ломающее
изменение формы — версия 2 и новая тема рядом со старой; подписчик на `.v1`
продолжает получать `.v1`.

В каждом теле есть `tenant_id` и `occurred_at` — они повторяют поля конверта и
переживают его в ваших журналах. Содержимого записи в теле нет ни у одной темы:
ни сумм, ни номенклатуры, ни назначения платежа, ни остатков, ни имён людей.

### Ядро

| Тема | Агрегат | Поля сверх общих |
|---|---|---|
| `core.document.created.v1` | `core_document` | `document_id`, `document_type`, `status` |
| `core.document.updated.v1` | `core_document` | те же |
| `core.document.posted.v1` | `core_document` | те же |
| `core.document.cancelled.v1` | `core_document` | те же |
| `core.document.marked_deleted.v1` | `core_document` | те же |
| `core.reference.item.changed.v1` | `core_dictionary_item` | `directory`, `item_id`, `item_code`, `change` |
| `core.reference.directory.changed.v1` | `core_dictionary` | `directory`, `change`, `created`, `updated` |

`status` — `draft`, `posted` или `cancelled`, и он стоит в теле КАЖДОГО события
документа. Нужны только проведённые — назовите это фильтром подписки
(`payload.status`): черновики отсеются до отправки, и ходить за ними в API не
придётся.

### Склад

`stock.reservation.placed.v1`, `stock.reservation.released.v1`,
`stock.balance.changed.v1`, `stock.inventory.counted.v1`,
`stock.inventory.acts_created.v1`, `stock.valuation.finished.v1`,
`stock.import.applied.v1`, `stock.warehouse.changed.v1`.

`stock.balance.changed` приходит по одному событию на пару товар×склад,
затронутую документом; количеств и себестоимости в теле нет — остаток вы
спрашиваете у отчёта остатков. Импорт публикует одно событие на прогон, а не по
одному на строку.

### Финансы

`finance.transaction.created.v1`, `finance.transaction.categorized.v1`,
`finance.transaction.uncategorized.v1`, `finance.statement.created.v1`,
`finance.import.applied.v1`, `finance.connector.synced.v1`,
`finance.payment_plan.executed.v1`, `finance.dividend_policy.approved.v1`.

`finance.transaction.uncategorized` — единственная тема финансов, несущая
назначение платежа: оно и есть предмет вопроса, и уезжает только тем установкам,
которых кабинет сам позвал классифицировать (точка
`finance.classification_provider.v1`). `finance.connector.synced` приходит на
каждый прогон, включая неудачный: «выписки не будет» — такой же факт, как
«выписка пришла».

### Задачи и календарь

`tasks.task.created.v1`, `tasks.task.updated.v1`,
`tasks.task.status_changed.v1`, `tasks.task.deleted.v1`;
`calendar.event.created.v1`, `calendar.event.updated.v1`,
`calendar.event.cancelled.v1`.

События календаря несут границы встречи и признак занятости — без них пришлось
бы читать карточку каждой встречи только затем, чтобы понять, попадает ли она в
ваше окно. Названий, описаний, ссылок на конференцию и списка участников в теле
нет.

## 7. Что проверяет SDK, а что — платформа

`akeda manifest lint` проверяет форму по схеме снимка и сверяет с каталогом
точки, слоты, места, вид слота на месте и поля контекста. По каталогу же
проверяются функции: точка существует и она песочничная. Локально, без Akeda,
проверяются и графы: ссылка только на собственный справочник этого манифеста,
подпись не из одних пробелов, ключ графы не объявлен у сущности дважды.

Живая таксономия областей доступа, ярус их чувствительности, сверка объявленных
граф с ПРЕДЫДУЩЕЙ опубликованной версией и наличие байтов у объявленного
отпечатка остаются за платформой при подаче версии: всему этому нужно то, чего в
снимке нет. Зелёный ответ здесь не означает, что версию опубликуют.

Каталог в снимке — состояние на момент съёмки. Пересняли контракт —
пересматривайте и манифест: место, которого платформа больше не держит, отвалится
на подаче версии, а не в рантайме.
