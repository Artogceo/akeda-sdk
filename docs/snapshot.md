# Снимок контракта

## Что в нём лежит

| Файл | Что это |
|---|---|
| `snapshot/openapi/akeda-v1.json`, `.yaml` | опубликованный контракт публичного API |
| `snapshot/extension-manifest/v1/manifest.schema.json` | JSON Schema манифеста расширения |
| `snapshot/extension-delivery/v1/delivery-contract.json` | форма подписи, конверт, пределы доставки и векторы |
| `snapshot/reference-data/v1/reference-data.schema.json` | схемы слоя ссылок на справочники |
| `snapshot/platform-catalog/v1/platform-catalog.json` | каталог точек расширения, слотов и именованных мест интерфейса |
| `snapshot/SNAPSHOT.json` | опись: версия контракта, числа, размеры и контрольные суммы |

## Откуда он берётся: единственное правило

**Снимок снимается ТОЛЬКО из опубликованных артефактов Akeda** — из того, что
Akeda уже отдаёт анонимному читателю справочника (`frontend/public/openapi/`).

Исходник контракта не читается **никогда**. В нём операторская половина системы
(контур поставки, издатели, волны раскатки, выдача токенов установок, ключи
подписи, журналы доставки по всем кабинетам) и расширение
`x-akeda-source-handler`, называющее внутренние методы и типы монолита.
Опубликованный артефакт отличается от исходника не объёмом, а составом.

Ошибка «взял исходник вместо публикации» тихая: файл разбирается, операций
больше, всё выглядит богаче. Поэтому она ловится машиной, а не глазами в ревью.

### Исключение: каталог точек, слотов и мест

Машинного артефакта с каталогом Akeda наружу не публикует, а без него проверка
манифеста знает про место только форму ключа — и принимает `crm.deal.sidebar`,
которого не существует. Разработчик узнаёт разницу на подаче версии, то есть
после того, как написал панель, которая никогда бы не показалась.

Поэтому каталог собирается разбором объявлений модуля `platform`
(`scripts/gocatalog.py`): ключи точек и мест, виды слотов, модели ответа, поля
контекста запуска, коды отказов — то есть ровно те имена, которые платформа и
так называет разработчику. Маршрутов, имён обработчиков и конфигурации в
каталоге нет: этим он и отличается от исходника контракта, который не читается
никогда.

Закрытые списки — поверхности, виды слотов, модели ответа, поля контекста —
снимаются с тех же констант платформы, а не пишутся в скрипте своей копией.
Копия разошлась бы молча: третья модель ответа, `sandbox`, появилась у точки
раньше, чем о ней узнал бы список в скрипте, — и снятие снимка отвергло бы
существующую точку как непонятную.

Разбор падает на первом непонятном объявлении и на пустом разделе. Каталог,
разобранный наполовину, — это проверка, которая молча начинает отвергать
существующие места, и выглядит она ровно так же зелено.

## Как снять

```bash
python3 scripts/snapshot.py --source <дерево Akeda ERP>
python3 scripts/generate.py
python3 scripts/scan_secrets.py
```

Скрипт снятия падает, если:

- в `--source` нет собранных опубликованных артефактов (значит, вам подсунули
  дерево без прогона `task openapi:generate`);
- в опубликованном контракте оказалась операция с аудиторией не `external`;
- в нём остался путь `/api/v1/platform/**`;
- в любом из копируемых файлов нашлась запрещённая подстрока — адрес дев-контура,
  имя сборочного сервера, имя клиентского ext-модуля, `x-akeda-source-handler`.

Ни один из этих отказов не чинится в снимке. Каждый означает дыру в конвейере
публикации Akeda, и чинить надо её.

## Повторяемость

**Времени снятия в снимке нет.** Метка времени сделала бы два прогона на одном
входе разными файлами, то есть уничтожила бы единственное свойство, ради
которого снятие вообще скриптуется. Кому и когда снимали, отвечает история git.

Опубликованные артефакты копируются **побайтно**. Единственный производный
файл — схемы слоя ссылок — собирается из контракта замыканием по `$ref` и
печатается канонически (`sort_keys`, отступ 2, перевод строки в конце): порядок
ключей входного JSON зависит от того, чем его собрали, и снимок, отличающийся
только порядком, читался бы как «релиз изменился».

Проверяется так:

```bash
python3 scripts/snapshot.py --source <дерево> && cp -R snapshot /tmp/a
python3 scripts/snapshot.py --source <дерево> && diff -r /tmp/a snapshot   # пусто
python3 scripts/snapshot.py --check                                        # опись сходится
```

То же у генератора типов: `python3 scripts/generate.py` дважды даёт побайтово
одинаковые файлы, а `--check` сверяет их с тем, что сгенерировалось бы из снимка
сейчас. Go-часть прогоняется через `gofmt` внутри генератора, а не отдельным
шагом: иначе `--check` сверял бы отформатированное с неотформатированным и падал
бы всегда.

## Чем снимок привязан к релизу

`SNAPSHOT.json` несёт:

- `contract.version` — версия из `info.version` опубликованного контракта;
- `contract.operations` — числа по стадиям, аудиториям и модулям плюс
  `installation_reachable`: сколько операций открыто токену установки и в каких
  модулях. По ним видно, что именно изменилось в релизе, ещё до чтения diff;
- `files[].sha256` — контрольная сумма каждого файла;
- `snapshot_digest` — общая сумма по списку «путь + сумма». Считается по списку,
  а не по склейке содержимого: тогда переименование файла меняет отпечаток так
  же, как правка байтов, а склейка переименование бы проспала.

Отпечаток печатает CLI:

```bash
go run ./cmd/akeda contract
```

Коммита Akeda в снимке нет намеренно: он ссылается на приватный репозиторий,
которого у читателя снимка нет, и ничего ему не доказывает. Релиз опознаётся
версией контракта и отпечатком, а они самодостаточны.

## Что генерируется из снимка

`scripts/generate.py` собирает типы для трёх языков **одним** генератором. Не
тремя: имя модели, имя операции и разбор одной и той же схемы обязаны совпадать
в TypeScript, Python и Go, а три инструмента разошлись бы на первом же `oneOf` —
и разошлись бы молча.

Генерируются только типы. Рантайм — аутентификация, листание, идемпотентность,
разбор отказа, проверка подписи — написан руками: это места, где принимаются
решения, а генератор решений не принимает.

В карту операций попадают не только метод и путь, но и то, что рантайму нужно,
чтобы вести себя честно: стадия, право, читает ли операция `Idempotency-Key`,
схема листания, объявленный потолок страницы и открыта ли операция токену
установки. Последнее — ось, которая не выводится ни из стадии, ни из права: без
неё расширение узнаёт, что операция ему закрыта, по `401` в проде.
