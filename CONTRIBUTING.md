# Как вносить правки

## Что можно править руками, а что нельзя

| Нельзя руками | Почему |
|---|---|
| `snapshot/**` (кроме `embed.go`) | снимок снимается скриптом из опубликованных артефактов Akeda; правка руками делает опись ложью, и `scripts/snapshot.py --check` это ловит |
| `clients/*/generated/**` | типы собирает `scripts/generate.py`; правка исчезнет на следующем прогоне, а расхождение поймает `--check` |

Всё остальное правится руками, и именно там живут решения. Разделение не
формальное: генератор решений не принимает, а типы, списанные руками, расходятся
с контрактом на первой же правке.

## Обновление снимка на новом релизе Akeda

```bash
python3 scripts/snapshot.py --source <дерево Akeda ERP>
python3 scripts/generate.py
python3 scripts/scan_secrets.py
```

Первый шаг откажется работать, если ему подсунуть исходник контракта вместо
опубликованного артефакта, и упадёт, если в опубликованном окажется операция,
не адресованная внешнему разработчику. Оба отказа — не придирка: они означают
дыру в конвейере публикации Akeda, и чинить надо её, а не снимок.

Дальше прогоните проверки (ниже) и посмотрите на diff `SNAPSHOT.json`: числа по
стадиям и модулям показывают, что именно изменилось в релизе.

## Проверки перед коммитом

```bash
python3 scripts/snapshot.py --check      # опись снимка сходится
python3 scripts/generate.py --check      # generated совпадают со снимком
python3 scripts/scan_secrets.py          # ни секретов, ни внутренних адресов

cd clients/typescript && npm install && npm test && cd -
cd clients/python && python3 -m pytest && cd -
gofmt -l . && go vet ./... && go test ./...
```

Всё это же гоняет CI. Публикации пакетов в нём нет и не появится: собрать —
можно, опубликовать — нет.

## Правила, которые стоит знать до правки

**Рантайм пишется руками, типы генерируются.** Если вам захотелось сгенерировать
метод на каждую из 770 операций — не надо: это ещё один список, расходящийся с
контрактом молча. Клиент типизирован сгенерированной картой операций.

**Числа контракта в тестах закреплены.** `770 операций`, `30 стадии public`,
`пять операций читают Idempotency-Key` — это не украшение теста, а замок: они
меняются вместе со снимком и никогда отдельно от него.

**Секрет не попадает в argv.** У CLI нет и не будет флага со значением секрета:
`ps` показывает аргументы процесса любому пользователю машины.

**Чего нет в контракте, того SDK не изображает.** Команда, делающая вид, что
умеет вызвать несуществующую дверь, врёт дважды: про существование вызова и про
право его сделать. Пишите отказ с объяснением, что доступно вместо этого.

**Тексты — по-русски, идентификаторы — по-английски.** Так же, как в самой
Akeda. Сообщение об ошибке объясняет, ЧТО делать дальше, а не только что
случилось.

## Коммиты и ветки

Ветка от `main`, коммит в повелительном наклонении по-русски, тело — почему, а
не что. Pull request проходит проверки выше; правка `snapshot/**` и
`clients/*/generated/**` допустима только вместе с прогоном скриптов, и это
видно по diff.

## Чего в этом репозитории не делают

- не делают его публичным и не заводят GitHub Pages;
- не публикуют пакеты и не заводят теги релиза, запускающие публикацию;
- не коммитят секреты, ключи и адреса внутренних служб;
- не копируют сюда исходник контракта Akeda и внутренние документы.
